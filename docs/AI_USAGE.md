# 《龙师零号》AIGC 使用与披露方案

版本：0.2  
用途：开发过程记录、赛事 AI 使用声明、版权与人工审核留档

## 1. 声明原则

本项目将遵循以下原则：

1. 明确记录 AI 工具、模型、用途、输入类型及人工修改过程。
2. 不把未经审核的模型输出直接作为最终游戏内容。
3. 不使用来源不明或明显模仿在世艺术家、影视作品、游戏角色的生成素材。
4. 不向模型提交真实个人信息、API 密钥或未获授权的保密内容。
5. 运行时 AI 只输出受约束的训练参数，不生成或执行任意代码。
6. 对外披露以实际使用情况为准，不把“计划使用”写成“已经使用”。

## 3. 计划使用方式

### 3.1 策划与文本

计划使用 AI 辅助：

- 提出玩法变体。
- 检查规则漏洞。
- 压缩对白和教学文字。
- 生成测试输入与边界案例。
- 起草报名材料。

人工负责：

- 最终世界观、角色弧线和价值表达。
- 所有对白的选择、改写与定稿。
- 文化事实核验。
- 删除空泛、重复或不符合角色语气的内容。

### 3.2 程序开发

计划使用 AI 辅助：

- 工程脚手架与模块初稿。
- Phaser 场景、交互和动画代码。
- 评分、离线解析和结构校验逻辑。
- 单元测试与端到端测试。
- 错误定位和重构建议。

人工负责：

- 明确接口与系统边界。
- 运行、调试和验证每项功能。
- 审核安全性、依赖和异常处理。
- 决定最终保留的代码。

代码占比不以简单“AI 生成行数”计算。最终声明采用“AI 辅助模块范围 + 人工验证方式”的表述。

### 3.3 视觉素材

首选方案是使用 Canvas、程序化纹理和原创模块化图形完成正式游戏画面。

如使用图像生成模型，限定用途为：

- 早期视觉方向探索。
- 原创构图草案。
- 纹理或氛围参考。

阿零、龙具和舞龙队必须先按 `docs/scenes/00A-核心形象与复用资产规范.md` 制作并锁定母版设定图。此后生成首页、训练、演出或结局场景时：

- 必须附带对应母版参考图，不得只靠文字提示重新生成。
- 必须在提示词和台账中记录资产ID、母版版本、姿态ID和场景实例。
- 允许改变构图、姿态、光照和环境，不允许改变角色比例、服装版型、龙头结构、固定纹样与磨损。
- 母版一致性未通过叠图验收的输出只能作为草案，不得进入游戏、海报、截图或宣传视频。

每张进入最终版本的生成图必须记录：

- 工具及模型版本。
- 提示词摘要。
- 使用的母版资产ID与版本。
- 参考图文件及授权状态。
- 生成日期。
- 人工绘制、重组和修订内容。
- 最终使用位置。
- 生成平台的商用授权状态。

禁止使用：

- 真实赛事标志和吉祥物。
- 现有影视、动画或游戏角色。
- 具体竹刻名作的复制品。
- “模仿某位在世艺术家”类提示词。
- 无法确认来源和授权的训练素材包。

### 3.4 音频

Demo 基础鼓点计划由 Web Audio 程序化合成，不属于 AIGC 音频。

如后续使用 AI 音乐、配音或音效：

- 保存生成平台授权条款截图或链接。
- 保存提示词与原始输出。
- 记录剪辑、混音和降噪步骤。
- 确认声音不模仿未授权的真实人物。

### 3.5 运行时大模型

运行时模型用于把玩家的一句训练口令转换为以下结构：

```json
{
  "stability": 60,
  "rhythm": 45,
  "coordination": 70,
  "expression": 25,
  "preferredMove": "lookBack",
  "avoidMove": "leap",
  "explanation": "先确认队形，再提高动作幅度。"
}
```

约束：

- 四项训练侧重只能为15–85的整数，合计固定为200。
- 动作只能来自本轮已解锁且已编入时间轴的预设枚举。
- 解释文本限制长度。
- 响应必须通过本地结构校验。
- 无效响应直接丢弃并进入离线规则。
- 模型无法直接改变剧情状态、文件、网络设置或可执行代码。
- 模型无法添加、删除或重排玩家已经编入鼓谱的动作。

## 4. 在线接口与隐私

### 4.1 密钥

- API 密钥只保存在本地环境变量。
- 不写入前端代码、截图、日志或提交材料。
- 浏览器只请求项目自己的服务端代理。

### 4.2 玩家输入

- 游戏明确提示口令会在联网模式下发送给第三方模型服务。
- 提示玩家不要输入个人信息。
- 默认不长期保存玩家原始口令。
- 宣传录像使用预设测试口令，不使用真实玩家数据。

### 4.3 离线模式

以下情况自动进入离线模式：

- 未配置 API 密钥。
- 网络不可用。
- 请求超时。
- 模型返回非法结构。
- 服务端触发限流。

离线解析通过关键词和句式识别稳定、节奏、协作与表现倾向，保证完整流程可玩。

## 5. 人工审核清单

每次加入 AI 产出前检查：

- [ ] 是否与项目需求直接相关。
- [ ] 是否包含未经授权的角色、商标、标志或作品元素。
- [ ] 是否存在事实错误或文化误读。
- [ ] 是否经过人工修改，而非直接复制。
- [ ] 是否能说明工具、模型和生成日期。
- [ ] 是否保存原始输出及最终版本。
- [ ] 是否确认平台允许相应商业用途。
- [ ] 是否在游戏内正常显示并通过测试。
- [ ] 是否更新使用占比和素材台账。

## 6. 素材台账模板

正式生产时，每项 AI 产出按以下格式追加记录：

```markdown
### AI-0001

- 资产名称：
- 共用资产ID：
- 母版版本：
- 姿态ID / 场景实例：
- 最终文件：
- 使用环节：
- 工具与模型：
- 生成日期：
- 输入或提示词摘要：
- 参考素材及授权：
- 原始输出保存位置：
- 人工修改：
- 最终采用比例：
- 审核人：
- 状态：草稿 / 已采用 / 已弃用
```

“最终采用比例”描述该资产中生成内容的保留程度，不代表整个项目的 AI 占比。

## 7. 占比计算建议

最终申报不使用一个缺乏依据的笼统百分比，而是按环节分别披露：

| 环节 | 建议统计口径 |
| --- | --- |
| 游戏策划 | AI 起草段落占初稿比例，以及人工重写范围 |
| 程序代码 | AI 辅助过的模块数量，以及人工测试与重构情况 |
| 视觉素材 | 最终采用的 AI 生成资产数 / 总视觉资产数 |
| 音频素材 | 最终采用的 AI 音频时长 / 总音频时长 |
| 文本对白 | AI 初稿后保留的句数 / 最终总句数 |
| 运行时 AI | AI 参与的功能范围，而非静态资产占比 |

所有数值在项目完成后从实际台账计算。
