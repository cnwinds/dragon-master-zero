# 《龙师零号》参赛Demo制作计划

版本：0.3  
计划周期：2026年8月19日—8月30日  
提交截止：2026年8月30日

## 1. 制作原则

1. 先完成一个可从编排走到评分的闭环，再增加剧情与美术。
2. 在线 AI 是增强项，离线完整可玩是提交底线。
3. 每天结束时都保留一个可以启动的版本。
4. 8月27日后停止增加机制，只修复问题和制作材料。
5. 完成度优先于内容数量，必要时删减场景而不牺牲核心循环。

## 2. 优先级

### P0：缺失即不能提交

- 动作竹简编排。
- 八拍时间轴。
- 训练口令解析。
- 离线兜底。
- 自主演出。
- 鼓点纠偏。
- 四维评分。
- 两条可选择的训练记忆。
- 三种互斥且可复现的结局。
- PC 浏览器完整运行。
- 可运行说明和 AI 使用声明。

### P1：构成完整参赛Demo

- 两轮训练与最终演出。
- 三种结局。
- 手机横屏适配。
- 水墨竹刻与机械蓝图视觉。
- 程序化鼓点。
- 开场、设置、重玩和本地存档。
- 自动测试。
- 宣传截图与60秒视频。

### P2：时间允许再做

- 结局画面下载。
- 英文字幕。
- 第二套鼓点难度。
- 训练口令历史。
- 幕后开发记录。
- 更多环境动画和粒子。

任何 P2 内容不得挤占 P0、P1 的测试时间。

## 3. 每日安排

### 8月19日｜策划冻结

目标：

- 确定核心主题、玩法、关卡、AI边界和技术结构。
- 完成基础参赛文档。

交付：

- `README.md`
- `docs/GDD.md`
- `docs/TECH_SPEC.md`
- `docs/ACCEPTANCE_CRITERIA.md`
- `docs/PRODUCTION_PLAN.md`
- `docs/AI_USAGE.md`
- `docs/SUBMISSION_COPY.md`
- `docs/TRAILER_SHOTLIST.md`

完成标准：

- 不再改变“训练而非直接操控”的核心。
- Demo明确限制为三段可玩流程。

### 8月20日｜工程与灰盒闭环

目标：

- 建立 Vite、TypeScript、Phaser 和测试工程。
- 完成单轮“编排—演出—评分”灰盒流程。

交付：

- 可启动工程。
- 六种动作的数据结构。
- 可填满的八拍时间轴。
- 纯逻辑演出事件生成器。

完成标准：

- 不需要美术，也能从编排界面进入评分结果。

降级决策：

- 若 Phaser 集成消耗过久，保留 Phaser 场景管理，复杂 UI 暂用 HTML/CSS。

### 8月21日｜演出与纠偏

目标：

- 完成确定性演出、动作衔接、失误和鼓点纠偏。

交付：

- 预测轨迹与实际轨迹。
- 五类可解释失误。
- 两次纠偏机会。
- 四维评分。
- 演出与评分单元测试。

完成标准：

- 相同输入重复三次，主要演出结果一致。
- 玩家能从画面看出失误原因。

### 8月22日｜交互与触控

目标：

- 完成PC与手机横屏核心交互。

交付：

- 鼠标拖放。
- 点选动作—点选拍位的替代操作。
- 口令输入浮层。
- 空格键与触控鼓面。
- 竖屏旋转提示。
- 第一轮首次玩家测试记录。

完成标准：

- PC和手机横屏均能完成一轮训练。
- 至少3名首次玩家中有2人能在120秒内完成合法八拍编排。
- 当天修复所有导致玩家无法理解“动作—口令—纠偏”职责的问题。

### 8月23日｜离线口令与三段灰盒

目标：

- 先用离线解析完成序章、两轮训练和最终演出的完整灰盒。

交付：

- 离线关键词解析。
- 四项训练侧重预算与行为差异。
- 两轮训练记忆选择。
- 三段流程串联。
- 至少一个结局尾声。

完成标准：

- 不配置任何在线接口时，可从标题完成到一个结局。
- 同一动作序列配合稳健和表现口令时，至少两项行为可见不同。

### 8月24日｜在线AI与叙事扩展

目标：

- 接入 OpenAI 兼容接口并完成异常降级，同时补齐角色反馈。

交付：

- 服务端代理。
- 环境变量模板。
- 严格输出结构。
- 4秒超时与固定缓存。
- 在线、缓存和本地解析状态。
- 周师傅、阿零和小满的基础对白。
- 基础训练场。
- 老街灯阵。
- 训练记忆继承。
- 角色反馈。

完成标准：

- 在线、无密钥、断网、超时、非法输出五种情况均可继续游戏。
- 浏览器包与日志不存在API密钥。
- 模型无法返回预算外数值或动作枚举之外的值。

删减规则：

- 若对白影响节奏，优先删对白，不删核心操作教学。

### 8月25日｜最终演出与结局

目标：

- 完成河岸灯会演出和三种结局。

交付：

- 最终自由编排。
- 队友被灯绳绊住的突发事件。
- 师傅信任、队伍同心和观众热度。
- 冠军机器、灯散之后、真正出师。
- 第二轮首次玩家测试记录。

完成标准：

- 三个结局都能通过明确的玩家行为进入。
- 不存在只有随机数决定的结局。
- 至少3名首次玩家中有2人能说明终局行为与此前训练有关，而不是一次直接按键选择。

### 8月26日｜视觉与音频整合

目标：

- 把灰盒提升为可展示版本。

交付：

- 宣纸、靛青、朱砂、旧铜、竹青视觉变量。
- 程序化水墨纹理。
- 竹简动作卡。
- 阿零正面、侧面、背面母版及统一骨骼锚点。
- 龙头正侧面、四段龙身、托杆与固定修补标记母版。
- 小满、周师傅和三名后续队员母版。
- 首页、训练、演出和结局共用的角色与龙具渲染模块。
- 灯阵模块化图形。
- 预测蓝线、实际竹青笔触、朱砂失误标记。
- 三套鼓点和反馈音。

完成标准：

- 五秒观察核心玩法画面后，至少4/5名测试者能指出阿零和下一步操作区域。
- 至少4/5名测试者能辨认“传统材料或水墨”与“机械技术”两种气质。
- 首页、第一轮演练和最终演出的阿零归一叠图后轮廓偏差不超过2%。
- 三个场景中的龙头角、眼、吻部、额纹、金须和颈根锚点一致。
- 不存在首页或结局专用的独立阿零、龙头绘制实现。
- 所有正式素材来源明确。

### 8月27日｜完整体验与功能冻结

目标：

- 串联完整流程并冻结功能。

交付：

- 标题、序章、三段玩法、结局、重玩。
- 音乐和音效设置。
- 本地进度。
- 字幕跳过。
- 首轮完整端到端测试。

完成标准：

- 从打开页面到任一结局无阻断错误。
- 完整体验控制在12–15分钟。

冻结规则：

- 当天结束后不增加动作、角色、场景、结局或新系统。

### 8月28日｜测试与修复

目标：

- 找出阻断问题、误导交互和设备适配问题。

交付：

- 单元测试全部通过。
- PC与手机横屏端到端测试。
- 无API模式测试。
- 累计至少五名首次玩家试玩记录。
- 三套标准行为路径自动化或固定预设验证。
- 问题按阻断、高、中、低分类。

完成标准：

- 阻断问题清零。
- 高优先级问题清零。
- 至少4/5名首次玩家通过核心循环、因果和主题验收。

### 8月29日｜宣传与报名材料

目标：

- 完成所有赛事提交素材。

交付：

- 五张1920×1080截图。
- 一张主海报。
- 60秒实机视频。
- 30秒备用版本。
- 最终玩法介绍。
- 最终AI使用清单与占比。
- 运行说明。

完成标准：

- 视频展示的全部功能都存在于提交版本。
- 文档不存在“待填写”“计划使用”或与成品不符的描述。

### 8月30日｜最终验收与提交

目标：

- 只处理提交、兼容性和材料错误，不进行功能开发。

交付：

- 最终生产构建。
- 本地完整备份。
- 提交包校验值。
- 官网报名材料。

提交前操作：

1. 在一台未配置开发环境的设备上按README运行。
2. 分别测试联网与断网流程。
3. 从压缩包重新解压并启动一次。
4. 检查视频、截图、海报和文档链接。
5. 检查所有联系人信息。
6. 提前提交，不把首次上传留到截止前最后一小时。

## 4. 每日构建规则

每天结束前执行：

1. 类型检查。
2. 单元测试。
3. 生产构建。
4. 从标题进入至少一次评分界面。
5. 将当日可运行版本单独归档。

任何一天如果生产构建失败，下一工作日首先恢复构建，不继续增加功能。

## 5. 范围降级顺序

工期不足时按以下顺序删减：

1. 英文字幕。
2. 结局画面下载。
3. 幕后开发记录。
4. 额外环境动画。
5. 第二套鼓点难度。
6. 将三个结局的独立演出缩减为共用演出加不同尾声。
7. 将序章改为短字幕与一段可交互失败演示。

不可删减：

- 动作编排。
- 自然语言口令。
- 离线兜底。
- 自主演出。
- 鼓点纠偏。
- 玩家训练影响结局。

## 6. 提交阻断条件

出现以下任一情况不得将当前版本标记为最终版：

- 断网后无法完成游戏。
- API密钥出现在前端包或文档。
- 存在无法关闭的报错界面。
- PC端关键按钮超出画面。
- 手机横屏无法输入口令或进行纠偏。
- 同一动作占用重复拍位导致流程卡死。
- 最终结局无法触发。
- 使用来源或授权不明的正式素材。
- AI使用声明与实际内容不一致。
- 宣传视频展示不存在的功能。

## 7. 最终完成定义

项目只有在以下条件全部满足后才算完成：

- [ ] 可运行Demo完整。
- [ ] 核心体验12–15分钟。
- [ ] 在线AI和离线模式均可用。
- [ ] PC和手机横屏可完成全部流程。
- [ ] 自动测试和生产构建通过。
- [ ] 三个结局可复现。
- [ ] 至少4/5名首次玩家通过统一体验验收。
- [ ] 五张截图、一张海报和实机视频完成。
- [ ] GDD、AI声明、运行说明和报名文案与成品一致。
- [ ] 所有素材通过版权检查。
- [ ] 提交包已经在干净环境验证。
